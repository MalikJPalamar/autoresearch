## ⚠️ Data-Source Failure: `scripts/prices.sh` Blocked at Network-Policy Level

`scripts/prices.sh --json` returned `NA` for all 18 tickers. Diagnosis via the session's agent-proxy status endpoint confirms this is **not a script bug or a transient flake**: both Yahoo Finance (`query1.finance.yahoo.com`) and Stooq (`stooq.com`) CONNECT attempts were rejected with **403 policy denial** by this session's egress proxy (`"gateway answered 403 to CONNECT (policy denial or upstream failure)"`). Per the proxy README, 403/407 responses are organization egress-policy blocks and are explicitly **not to be retried**.

Per format-011 protocol, when the primary source is unavailable the fallback is WebSearch for every ticker, with each price subjected to the same verification checks. That fallback was used for **all 18 tickers today** (not just NA exceptions), and it surfaced the widest spread of source disagreement seen since format-011 began: several tickers had multiple WebSearch sources disagreeing by 1–3% or more on the same day's close, two tickers (ASML, and to a lesser extent BAH) returned no confirmed Aug 21 print at all, and one ticker (NRG) had a 20%-wide spread across sources including one likely-bad outlier. Where a ticker's plausible price range could flip its 5-day accuracy score across a scoring boundary, that ticker was marked **UNVERIFIED and scored PENDING**, not estimated, per the fail-safe rule. Where the range was wide but did not change the scoring verdict, the score was kept with an explicit confidence flag (this mirrors precedent set in the Aug 20 report for SMR).

**Action item for a human:** if this environment's network policy is expected to allow financial data sites, someone with access to the session/organization network configuration should check why `query1.finance.yahoo.com` and `stooq.com` are being denied — this will recur every session until fixed, and materially degrades price precision versus the intended `prices.sh`-primary design.
